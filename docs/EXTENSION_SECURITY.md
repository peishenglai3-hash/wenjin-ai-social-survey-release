# 第三方技能与扩展安全边界

问津当前的开放生态只允许“声明式 prompt 技能”进入公共市场。社区技能可以被查看、复制到自己的私有技能库，再由拥有者主动调用；服务端不会加载社区代码、动态 import、执行 Python/JavaScript、运行工具链或把社区字段当作模板语言。

## 当前允许的能力

- 公共技能是文本、标签、示例和兼容模型元数据。
- `skill_type` 即使写成 `rule_chain` 或 `custom_workflow`，当前公共运行时仍把它视为 `prompt_only`，不会获得额外执行能力。
- 私有技能调用只做受限的字面 `{name}` 替换；嵌套对象、超长上下文和未知模板语法不会触发解释器。
- 发布入口拒绝明显的凭据、私钥、脚本/动态执行标记，并限制字段长度。

## 明确不提供的能力

公共技能不能直接访问数据库、文件、网络、供应商 key、受访者原始资料、系统命令或其它用户的项目。未来如果要引入工具调用、工作流或 WASM/容器扩展，必须另立版本，先完成能力声明、最小权限、沙箱、超时/资源配额、审计和独立安全测试；不能把现有 `prompt_template` 字段升级成隐式代码执行入口。
